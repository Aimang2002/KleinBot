# 卷 18 · 支撑模块：日志、版本、服务器状态、搜歌、工具函数

> 源码基准：`src/Log/`、`src/Version/`、`src/ComputerStatus/`、`src/submodules/CloudMusicID/`、`src/utils/Utils.hpp`。这些模块小而独立，一并收录。

## 1. Log——异步文件日志单例（Log.h/.cpp）

### 1.1 结构

- 单例 `getInstance()`：`call_once` 里 `initThread()`；初始化失败（目录建不了/文件开不了）**抛 runtime_error**——日志是硬依赖。
- 文件：`logs/YYYY-M-DD.log`（**按本地日期一个文件**，追加模式）；目录不存在自动建。
- 后台线程：`cv.wait(队列非空 || !isRunning)` → 逐条 `record`（写文件+endl）。**INFO/DEBUG 不进队列**（只有控制台），WARNING/ERROR/FATAL 才入队落盘。

### 1.2 各级别行为

| 宏 | 控制台 | 文件 | 颜色 |
| --- | --- | --- | --- |
| `LOG_INFO` | ✔ | ✘ | 绿 |
| `LOG_DEBUG` | 仅 `#ifdef DEBUG` 编译进（Release 直接 `(void)0`） | ✘ | 橙 |
| `LOG_WARNING` | ✔ | ✔ | 黄 |
| `LOG_ERROR` | ✔（stderr） | ✔ | 亮红 |
| `LOG_FATAL` | ✔（stderr） | ✔ | 红 |

### 1.3 messageLengthCheck

超过 1024 字节截断：逐字节走，`>0x80` 认为汉字占 3 字节——**该 UTF-8 判断不精确**（首字节才是 0xF0 系 4 字节等），极端情况下截断点可能落在多字节中间；纯展示问题，不影响运行。截断加 `"..."`。

### 1.4 shutdown

`isRunning=false` → notify → join（**线程退出前排空队列**——优雅退出最后一步就是它）→ 关文件。幂等（isRunning 已 false 直接返回）。

已知边界：`LOG_INFO` 多线程并发 `localtime`（非线程安全）；日期翻转（跨午夜）不换文件——日志仍写旧日期文件。

## 2. Version——`--version` 输出（VersionInfo.h/.cpp）

- `formatBuildTime(__DATE__, __TIME__)`：把 `"Aug  5 2026"` + `"20:45:12"` 重排成 `"2026-08-05 20:45:12"`（月名表查索引；日不足两位带前导空格——模板注释点名）；解析失败原样拼接。
- `libcVersion()`：glibc（`__GLIBC__`）返回如 `"2.35"`，否则 `"N/A"`（MSVC/MinGW 无标准接口）。注意必须**先 include 标准头再判断 `__GLIBC__`**（宏由标准头带出）。
- `summary()`：7 行对齐输出（版本/Git 提交/构建时间/构建类型/编译器/libc/架构），标签按显示宽度手工对齐（中文 2 半角宽）。

## 3. ComputerStatus——服务器网络查询（管理员命令后端）

| 方法 | 实现 |
| --- | --- |
| `getInet4()` | Linux: `getifaddrs` 遍历 AF_INET 逐网卡 `inet_ntop`；Windows: `GetAdaptersAddresses`。输出多行 `"IPv4 Address: x.x.x.x\n\n"` |
| `getInet6()` | 同上 AF_INET6 版 |
| `getPublicIP()` | 依次 GET `http://ip.3322.net`（IPv4）与 `http://ipv6.icanhazip.com`（IPv6），响应体原样拼接标签返回 |

未设置超时、未接入取消机制（简单运维路径，属可接受范围）。

## 4. CloudMusicID——网易云搜歌（submodules）

`searchSong(name)`：GET `https://music.163.com/api/search/get/web?s=<名字>&type=1&limit=1`（自定义 urlEncode：非 ASCII 字符转为 %XX 大写十六进制，保留 `:/?=&`）；UA 设置为 Chrome 浏览器标识；返回解析后的 JSON（`result.songs[0].id` 由 SearchSongsCommand 提取）。curl 初始化失败、请求失败或解析失败统一返回空 JSON。

## 7. CapabilityBroker——实现端能力协商（Application/CapabilityBroker.h/.cpp，T2）

一套代码设计（D12）：业务层只认识自定义能力词汇 `BotFeature{InputStatus, GroupPoke}`，实现端名字（NapCat/LLOneBot/…）永远到不了业务分支——它们的唯一身份是往静态能力表 `featureSupported(appName, feature)` 填数据（按 `get_version_info` 的 app_name 大小写不敏感宽松匹配；未列出的实现端全 false）。能力准入按三标准评审，新能力 = 枚举加一项 + 表加一列 + 消费处一次查询。

状态机：`poll(now)` 由 pollingThread 每 3s 调用；未就绪时经注入的 `VersionProbe`（生产 = `activeApiChannel.call("get_version_info", …, 5s)`，WS 模式 WebSocketApiChannel / HTTP 模式 HttpApiChannel）同步探测，成功 → 解析 `appNameFromInfo` → 查表缓存能力位 + 日志摘要，**终态不再重探**；失败 → 60s 冷却后由下一轮 poll 重试。`supports()` 在未就绪/不支持时一律 false——功能静默关闭，主路径无感。当前能力位：InputStatus 仅 NapCat（LLOneBot 存疑按关，试调用探测因跨传输不可靠而暂缓）；GroupPoke = NapCat + LLOneBot。

## 7.5 TypingIndicator——私聊"正在输入"（Application/TypingIndicator.h/.cpp，T5）

`begin(userId)` 在私聊聊天路径、LLM 调用前触发一次 `set_input_status`（能力位门控，NapCat 才发）。fire-and-forget：1s 超时、结果静默丢弃，绝不阻塞回复主链路；**不发送取消**——回复消息到达或客户端超时自然清除（取消动作各实现端语义不一，暂不引入）。Message 以可空指针持有（`TypingIndicator *typingIndicator = nullptr`），测试可传 nullptr；群聊/命令/错误提示路径不触达。
