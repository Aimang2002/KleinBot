## 场景 1：私聊普通文本消息（主干路径）

用户（QQ 10001）私聊发"你今天过得怎么样"。

```
1.  协议端 → 客户端模式 WS 连接（Klein 监听 127.0.0.1:8600/onebot）推送事件 JSON
    [卷05 §4] 鉴权/路径已在升级时校验过；会话循环 read 完成
2.  OneBotEventDecoder.decode [卷05 §8.2]
    post_type="message" → 产出 InboundMessage{user_id=10001, message_type="private",
    raw=plain="你今天过得怎么样", payload_size_bytes=…}
3.  InboundMessageQueue.push [卷06 §5]
4.  主循环 ≤100ms 后 tryPop 命中 → 私聊纯文本先进 InboundCoalescer 连发桶，静默 1.5s 后整桶 → messageWorkers.submit(10001, 任务)（群聊/命令/图片直通）[卷03 §8、卷07 §4]
5.  KeyedTaskScheduler：用户 10001 的 lane 进入 readyKeys，由某 worker 取得 [卷07 §3]
    （此刻同用户的后续消息在 lane 中排队等待——串行保证）
6.  workingThread [卷03 §9]
    长度：payload_size_bytes ≤ 4096×3 通过
    messageFilter("private")：size≥4 且非群 → 放行
7.  Message::handleMessage [卷07 §5.2]
    classify → Chat；registry.execute("你今天过得怎么样") 全部 canHandle false → nullopt
    无图片
8.  ChatService::reply(user=10001, text, 无图) [卷10]
    8.1 user 消息写穿落库（内存镜像 + SQLite），返回 user_message_id
    8.2 buildChatRequest [卷12 §4]：模型查找（默认模型）→ history 快照（token 水位算法；锚点前移时带出 evicted_lines，ChatService 锁外合并滚动摘要）
    8.3 history 裁切结果（首句即本条）；tools=13 类 schema；system_prompt=人格+图片规则+(搜索/抓取/提醒 段)
    8.4 recallForMessage [卷14 §7]："你今天"不含召回词也不像事实问句 → 空串，不注入
    8.5 dock.RequestChat → OpenAIStandard [卷11 §5]
        payload 构造 → curl POST（300s/300s，5 次传输重试）→ 200 响应解析
    8.6 finish_reason="stop" 无 tool_calls → 退出循环
    8.7 落库 assistant 回复并入长期记忆提取队列 [卷14]
9.  Message：dispatchText [卷07 §5.4]（私聊整条单发，换行保留；超 4096 字符才硬切）→ sender.send_private
10. 出站队列 → WS 会话 50ms 循环出队 → OneBotMessageEncoder [卷05 §8.3]
    {"action":"send_private_msg","params":{"user_id":10001,"message":[{text…}]}}
11. 协议端发到 QQ。用户看到回复。
```

    （c44abf5 起后续段也带 execution_id#n，只聚合 message_id，不驱动状态）

## 场景 9：断线重连与优雅退出

```
断线（客户端模式 WS）：
    会话 async_read 返回错误 → 抛 system_error → 外层 catch LOG_ERROR
    "WebSocket（客户端模式）已失联（监听 bind:port），10秒后将重新连接..." → waitForReconnect（100ms 粒度可中断）
    重新 accept（协议端重连时重新走 Upgrade/鉴权/路径）
    ★ 会话中断期间：入站事件丢失（协议端若无重发机制）；
      出站消息仍在队列里，重连后照发（除非塞满）
优雅退出（Ctrl+C）：
    1st 信号：receivedSignal=2；主循环发现 → running=false [卷03 §2]
    资源回收链 [卷03 §11]：
      调度器 shutdown：排队任务丢弃，活动任务（可能正在模型 HTTP 中）继续
      活动任务里的 curl progress 回调发现 running=false → ABORTED_BY_CALLBACK
        → 适配器 cancelled=true → ChatService 直接返回（不解析不落库不续工具）[卷11 §5.3, 卷10]
      memoryService.shutdown：pending 丢弃，worker join（进行中的提取 epoch 检查后放弃写）
      定时/传输/面板线程逐个 join（各自的 100–200ms 粒度观察）
      Log::shutdown：日志队列排空
    退出期间 2nd Ctrl+C：_Exit(130) 立即死
```

## 附：三类典型错误路径速查

| 现象 | 路径 |
| --- | --- |
| 模型 500/超时 | 适配器合成 error envelope(503/504) → ChatService code≠200 → `"系统提示：模型请求超时…"` 发送至用户；上下文模式下 user 行已落库但无对应 assistant 行 |
| 队列满 | submit 返回 Full → 直接 sendError("系统繁忙")（不经调度器）[卷03 §8](03-启动与生命周期.md#8-线程启动435472) |
| 配置热刷新 | `#刷新配置文件` → AdminControlAction.refresh → `ConfigReloader::reload()` → 校验通过则发布快照 + 按规则表归类，带应用函数的行把新值换进活值（2026-11-15 起 54 个键重载即生效）→ 反馈文本回发（“已生效 X 项”，另列只能重启的路径）；持活值的模块从下一次操作起用新值，只能重启的 35 个键仍按启动值 [卷04 §5](04-配置系统.md#5-配置快照规则表与重载入口configsnapshotstore--configrules--configreloader) |
