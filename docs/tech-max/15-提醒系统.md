# 卷 15 · 提醒系统：持久化、内存队列与时间算法

> 源码基准：`src/Reminder/ReminderService.h/.cpp`、`src/Reminder/ReminderTime.h`、`src/Persistence/ReminderStore.*`、`src/Action/Set/List/CancelReminderAction.*`（Action 层见[卷09 §6](09-Action与Tool体系.md#6-全部-13-个模型工具详解)）。三个角色分工：**Store 管"怎么存"，Service 管"什么时候响"，Action 管"模型怎么用"**。时间解析完全交给模型（自然语言→ISO 时间），工具侧只做严格校验。

## 2. ReminderTime.h：三个纯函数（全 inline，可单测）

### 2.1 parseIsoLocal——带往返校验的严格解析

```
输入必须是恰好 16 字符的 "YYYY-MM-DDTHH:MM"（第10位也接受空格）；
逐位校验数字与分隔符位置（防 "2026-8-5T9:3" 这类）；
tm 字段范围粗查（mon 0-11, mday 1-31, hour 0-23, min 0-59）；
mktime(&parsed) —— mktime 会【原地归一化】越界字段（2月30日→3月2日）；
★ 关键：保留 original 副本，localtime(seconds) 回读后逐字段比对，
   任一不等 → nullopt（拒绝 mktime 静默滚动出来的非法日期）
```

为什么必须往返：不这么做，"2 月 30 日"会变成"3 月 2 日"被悄悄接受，用户以为设的是 2/30。

### 2.2 formatLocal / nowSeconds

`"%Y-%m-%d %H:%M"` 本地时区展示；unix 秒。

### 2.3 nextOccurrenceAfter——整除一步滚动

```
period = daily?86400 : weekly?604800 : 0(→返回0)
scheduledAt > now → 原样返回
periods = (now - scheduledAt) / period + 1
return scheduledAt + periods * period      // 严格大于 now 的下一次
```

一次除法代替逐周期循环；即使落后一整年也能一步跳到"最近的未来"。

## 3. ReminderService

### 3.1 内存队列结构

```cpp
std::map<int64_t, std::vector<DueEvent>> queue;   // key=触发秒；同秒多事件用 vector
std::mutex queueMutex;                             // 保护 queue（排队/取消/触发一致性）
```

同秒 vector 的设计源于历史问题：旧 `TimingTast` 模块的单值 map 会导致同秒事件相互覆盖，该模块已随重构删除并修复。`DueEvent{id,user_id,content,scheduled_at,repeat_rule,late}`；`late=true` 标记重启补发的漏触发事件（渲染时致歉）。

### 3.2 构造：重启恢复（构造函数全部逻辑）

遍历 `store.loadPending()`（全表升序）：

| 情形 | 处理 |
| --- | --- |
| 未到期（trigger_at > now） | 正常入队 |
| 漏触发且 repeat≠none 且 错过 ≤24h（kLateWindowSeconds） | **只入队补发迟到事件，不滚动**——popDue 触发时自然滚动到下一次（避免"构造滚动+触发滚动"双重入队） |
| 漏触发且 repeat≠none 且 >24h | 不补发，`nextOccurrenceAfter` 滚动落库 + 入队未来事件 |
| 漏触发且 none 且 ≤24h | 入队补发（late=true），触发时 popDue 删行 |
| 漏触发且 none 且 >24h | **deleteById 丢弃** + WARNING（原定时间） |

补发/丢弃计数 >0 时 INFO 汇总"提醒队列重建完成：补发 X 条，丢弃 Y 条"。

### 3.3 add / cancel / popDue

- `add(user,content,at,rule)`：content 空/规则非法 → 0（**时间合法性由 Action 层保证**，这里只做底线校验）；先 insert 落库（0=失败），再锁内入队。
- `cancel(user,id)`：id≤0 false；锁内扫队列找到 id：**归属不匹配 → false**（防止模型伪造编号跨用户删除）；删队列项 + deleteById。队列中没有（理论上不应发生）→ 按归属兜底查库删除。
- `popDue(now)`：锁内循环取走全部 `key<=now` 的桶；每事件：none → deleteById；daily/weekly → `nextOccurrenceAfter(scheduled_at, rule, now)` 滚动落库 + 以新时间重新入队（late 复位 false）。**整批原子**返回。

### 3.4 与定时线程的配合（卷03 §10）

3 秒轮询 → 每条 DueEvent 构造渲染 prompt（含当前时间、原委托；late 加致歉说明；口吻由人格装配决定，不再硬编码 bot 名）→ replyInCharacter → 空则兜底直发原文 → 私聊。**渲染与发送在定时线程串行**——大量同时到期的提醒会排队送达（可接受：提醒不需要秒级并发）。

## 4. 常量与上限

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `kMaxPendingPerUser` | 20 | 每用户待触发上限（Action 层校验） |
| `kLateWindowSeconds` | 86400 | 补发窗口 24h |
| 轮询周期 | 3s | 定时线程 sleepWhileRunning |
| 内容上限 | 1500 字节（≈500 汉字） | SetReminderAction 校验 |

## 5. 时间语义注意（时区/DST）

- 全部 `localtime/mktime`（`tm_isdst=-1` 让系统决定夏令时）——**提醒时间与部署机器时区绑定**；换时区部署，历史提醒的触发点含义会漂移。
- daily/weekly 的 86400/604800 是**固定秒差**，DST 切换日"每天9点"会偏 1 小时（未做钟点保持）。当前接受此简化。
