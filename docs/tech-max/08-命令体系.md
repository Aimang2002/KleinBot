# 卷 08 · 命令体系：Command 接口、注册表与 13 个命令

> 标题里的个数没有随命令的删除更新：现在 `main.cpp` 注册 11 个命令（11 次 `registryCommand`，见 §1 注册顺序），有的命令带多个写法。

> 源码基准：`src/Command/`。命令 = 用户以 `#` 开头显式触发的确定性操作，与"模型自主决定"的 Tool（[卷09](09-Action与Tool体系.md)）互补。

## 1. 接口与分发

```cpp
// Command.h
struct CommandContext { uint64_t user_id; uint64_t group_id; std::string message_type; const InboundMessage &data; };
struct CommandResult { OutboundMessage payload; };        // 语义消息，不拼 CQ 码

class Command {
    virtual bool canHandle(const std::string &message) = 0;   // 参数是去空白后的 plain_text
    virtual CommandResult execute(const CommandContext &ctx) = 0;
    virtual bool requiresAdmin() const { return false; }
    virtual std::string help() const = 0;
};
```

`CommandRegistry`（CommandRegistry.cpp）：

```
execute(message, ctx):
  按注册顺序线性遍历，第一个 canHandle==true 的命令：
    requiresAdmin && ctx.user_id != managerId → 返回 TextMessage{"权限不足！"}
    否则 → c->execute(ctx)
  全不匹配 → nullopt（调用方继续走聊天路径）
```

三项特性：**顺序优先**（注册顺序即匹配优先级，首个命中的命令生效）；**管理员校验集中于注册表**（由命令自行声明 requiresAdmin）；**权限失败亦返回明确结果**（用户会收到"权限不足"提示，而非无响应）。

注册顺序（`main.cpp`）：Help → ModelList → SearchSongs → QueryModel → GeneratePicture → ResetChat → ResetContext → SetSoul → SwitchModel → RemoveContext → Admin。

## 2. 命令逐个详解

### 2.1 HelpCommand（`#帮助` / `help`）

- canHandle：**全等匹配** `message == "#帮助" || message == "help"`。
- execute：`kHelpText`（HelpText.h 硬编码帮助全文）+ 当前版本行（`KLEINBOT_VERSION_STRING (KLEINBOT_GIT_HASH)`）+ "Create:@埃芒"。
- 注意 `help` 是**不带 #** 的匹配——群里 "@bot help" 解析出的 plain_text 就是 `help`，能正常触发。

### 2.2 ModelListCommand（`#模型列表`）

全等匹配。遍历 `ModelRegistry::all()` 把每条 ChatModel 的 modelList 全部名字列成 `"当前装载的模型如下：\n\n名字\n…"`；空表返回"未装载其他模型"。

### 2.3 QueryModelCommand（`#查询当前模型`）

全等匹配；构造空 JSON 参数调 `GetCurrentModelAction`（[卷09](09-Action与Tool体系.md)）的 execute，把 `result.content`（"当前模型：xxx"）回发。**命令与工具共用同一 Action 实例**。

### 2.4 SwitchModelCommand（`#切换模型:<name>`）

- canHandle：`check_command_exists(message, m_cmd)`（m_cmd=`#切换模型`）——前 `len+3` 字节里找 `#切换模型:` 或 `#切换模型：`。
- execute：`CP_split(plain_text, "#切换模型")` 提取参数（半角冒号取 `cmd:` 后全部；全角冒号取 `cmd：` 后全部）→ trim → `registry.find(name)` 不存在返回"未找到模型名称！"；存在则 `userSession.switchModel(user_id, name)`（只改内存，重启回默认）→"模型切换成功。"。

### 2.5 SetSoulCommand（`#设置人格:<text>` / `#人格还原`）

- canHandle：`message == "#人格还原"` 或 `check_command_exists(message, "#设置人格")`。
- 还原：`userSession.resetPersonality`（删 user_persona 行 + **重读 soul.md**，管理员改默认人格无需重启；同时按轻重置语义清空上下文窗口——人格切换即新对话起点，旧人格口吻的上下文不压在新人格上）→"人格还原成功。"。
- 设置：CP_split 提取描述 → 空 → "未找到人格描述！"；否则 `setPersonality`（内存 + SQLite 持久化）→"人格更新成功。"。

### 2.6 ResetChatCommand（`#重置对话`，轻重置）

全等匹配 → `userSession.resetChat(user_id)` →"对话重置成功。"。语义（[卷12 §5](12-用户会话与上下文.md#5-三种重置删除语义精确对照表)）：清内存镜像 + 上下文起点落库；**SQLite 历史、长期记忆、图片全保留**。

### 2.7 ResetContextCommand（`#重置上下文`，彻底重置）

全等匹配 → `resetContext`（清内存 + 清库 + 清记忆 + 清图片 + 起点归零；**人格保留**）→"上下文已彻底重置，对话、长期记忆与图片资源全部删除。"

### 2.8 RemoveContextCommand（`#删除上条对话` / `#rewind` / `#undo`）

三个别名全等匹配 → `removePreviousContext`（[卷12 §6](12-用户会话与上下文.md#6-removepreviouscontext-逐步169191-行)）→ 返回"上条对话已被删除！"/"没有上下文！"。

### 2.9 （已删除）VoiceSwitchCommand（`#开启语音` / `#关闭语音`）

2026-11-16 删除（ADR-025）：没有每人语音模式，用不用语音由她按对方是否明确要求决定（`send_voice` 工具，[卷09 §6.3](09-Action与Tool体系.md)）。管理员的 `#激活语音` / `#冻结语音` 保留，是语音总开关。帮助文本随之删去这一条，后面三条序号前移。

### 2.10 SearchSongsCommand（`#搜歌:<name>`，含全角冒号）

- canHandle：`message.size() > 10` 且前 10 字节含 `#搜歌:` 或 `#搜歌：`（半角冒号 1 字节、全角 3 字节，所以前 10 字节足够覆盖两种）。
- execute：`commandPromptDraw(plain_text)` 提取歌名（同 CP_split 逻辑的变体）→ `CloudMusicID::searchSong`（[卷18](18-支撑模块.md)）→ 取 `result.songs[0].id` → 0 则"未搜索到歌曲。"；否则 `MusicMessage{song_id}`（QQ 卡片由协议端渲染）。

### 2.11 GeneratePictureCommand（`#图片生成:<prompt>`，别名 `#生成图片`）

- canHandle：`check_command_exists(message, "#图片生成") || check_command_exists(message, "#生成图片")`。
- execute：CP_split 依次尝试两个前缀取 prompt（空 →"提示词为空！"）→ 现场构造 ChatModel（drawing 端点）→ `dock.RequestDraw` → `code>=400` →"网络异常！"；否则 `ImageMessage{Base64, image_base64}`。**命令路径生图不落资产库**（与 generate_image 工具不同：工具会存资产+占位符，这里直接把 base64 扔给出站编码）。

### 2.12 AdminCommand（6 个管理员命令的网关）

- canHandle：trim 后查集合 `{"#刷新配置文件","#激活语音","#冻结语音","#获取服务器inet4","#获取服务器inet6","#获取服务器公网IP"}`。
- `requiresAdmin()` **委托给 Action 描述符**（`action.descriptor().requires_admin` = true），非管理员得到注册表的"权限不足！"。
- execute：plain_text trim 后查表映射成 `arguments["action"]`，调 `AdminControlAction`；空结果兜底"操作失败，请查看日志定位问题。"。

### 2.13 FeedbackCommand（`#好` / `#坏`，可带备注，所有人可用，R0.3 2026-10-28）

已移除（经历层 E2，ADR-028）：`FeedbackCommand` 与 `RecordFeedbackAction` 一并删除，帮助文本里也没有这两个命令。`affect_feedback` 里旧的 `manual_admin` / `manual_user` 行照旧可读；现在的反馈来自当场察觉与回想（[卷13 附](13-持久化层.md#附人物卡取用与回想用到的存储adr-029adr-030adr-032)）。

### 2.13.1 KnowledgeCommand（`#教她` / `#查看认识` / `#撤回认识` / `#回滚认识` / `#清除认识`，管理员，经历层 E2，ADR-028）

已移除（经历层 E2，ADR-028）：五个账本命令与 `KnowledgeCommand` 删除，改为只在管理员私聊里开放的三个工具 `remember_guidance` / `review_guidance` / `forget_guidance`——部署者在私聊里直接说，记不记、记成什么由她判断（[卷09 §6.15](09-Action与Tool体系.md#615-认识账本三工具-remember_guidance--review_guidance--forget_guidance经历层-e2adr-028)）。回滚不对外。

### 2.14 与命令同名的自然语言入口

`#查询当前模型`、管理员命令两者都有 ActionTool 形态（get_current_model / admin_control），模型可在对话中自主调用——同一个 Action 两个入口，行为一致（见[卷09](09-Action与Tool体系.md)）。

## 3. utils 命令工具函数（Utils.hpp，字节级细节）

```cpp
// 前缀提取：在前 len(command)+3 字节里找 "cmd:" 或 "cmd："
check_command_exists(message, command):
    subs = message.substr(0, command.size()+3)
    return subs 含 "command:" 或 "command："
```

- `+3` 是为了容纳全角冒号（UTF-8 占 3 字节）。**这是字节级匹配**，中文命令名按字节比较，UTF-8 编码下安全。
- `CP_split(message, command)`：命中半角冒号 → `message.substr(command.size()+1)`；全角 → `+3`。**不做 trim**（调用方自己 trim）。
- `commandPromptDraw`：前 10 字节内找任意冒号（半角/全角），取其后——比 CP_split 宽松，专给 `#搜歌`。

注意事项：命令匹配与参数提取统一使用 **plain_text**（无 CQ 码，解码器已去首尾空白）——`CommandRegistry::execute` 收到的就是它。历史上的 v2.4.1 之前用 raw_message 匹配：群聊里 @ 机器人后 raw 变成 `[CQ:at,qq=x] #帮助`，全等命令（`==`）永远不命中、命令实际只对私聊可靠；改用去空白 plain_text 后群聊/私聊行为一致，"@bot #帮助" 与 "  #帮助  "（手滑多打空格）都能命中。raw_message 不再参与任何匹配。
