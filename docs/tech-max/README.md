## 术语表（入门版）

| 术语 | 通俗解释 |
| --- | --- |
| **OneBot** | 一个社区约定：QQ 机器人框架（协议端，如 LLOneBot）对外暴露什么样的 JSON 接口。KleinBot 不是 QQ 客户端，它只和协议端说话 |
| **协议端** | 真正登录 QQ 账号的程序（LLOneBot / NapCat 等）。它把 QQ 消息翻译成 OneBot JSON 发给 KleinBot，也替 KleinBot 把回复发出去 |
| **服务器模式**（原“正向 WS”，配置值 `forward_websocket`） | 协议端作 WebSocket 服务器，KleinBot 主动连出去（此模式下 KleinBot 是客户端） |
| **客户端模式**（原“反向 WS”，配置值 `reverse_websocket`） | 协议端作 WebSocket 客户端，主动连入 KleinBot 开的端口（此模式下 KleinBot 是服务端） |
| **Universal 连接** | 一条 WebSocket 同时收事件、发动作，不分两条 |
| **Agent Loop** | "模型说要调工具 → 程序执行工具 → 把结果塞回给模型 → 模型继续想" 的循环，直到模型给出最终文字回答 |
| **Function Calling / 工具调用** | 模型 API 的标准能力：模型不直接回答，而是返回"请帮我执行名为 X 的函数，参数是 Y"，由程序执行后回灌 |
| **CQ 码** | OneBot 里表示 @、图片等富媒体的文本格式，如 `[CQ:at,qq=123]` |
| **上下文窗口** | 发给模型的历史消息列表。KleinBot 内存里存全量，发之前裁切 |
| **长期记忆** | 后台用另一个模型从对话里提取出的"用户偏好/事实"数据，存在 SQLite，聊天时按需检索 |
| **组合根** | `main()` 函数。所有长生命周期对象在此创建并完成相互装配，其余模块仅持有引用 |
| **端口/适配器（Port/Adapter）** | 一个抽象基类（端口）+ 各家具体实现（适配器）。例如 LLMPort 有 OpenAIStandard、AnthropicStandard 两个实现，业务代码只认端口 |
| **WAL** | SQLite 的写前日志模式，读写并发更稳。KleinBot 所有库都用它 |
| **epoch** | 每用户计数器。删除数据时 +1，后台异步任务发现计数变了就丢弃旧结果，防止"删掉的旧数据被后台任务重新写回" |

## 与现有文档的关系

- `docs/technical-design.md`：正式设计与实现事实来源，偏概览；决策记录（ADR）在 `docs/adr/`，一条一个文件。本套文档是其深度展开版本，颗粒度细化至函数与字段。
- `README.md`：用户视角的安装/配置说明。本套文档[卷04](04-配置系统.md) 的配置参考手册是其开发者视角的扩展。
- 本套文档中发现的部分代码与 `technical-design.md` 的偏差已在各卷标注（例如：工具循环当前没有"证据综合阶段"状态机；`config.example.json` 残留已废弃的 `chat.private_action/group_action` 键）。
