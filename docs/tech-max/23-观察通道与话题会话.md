## 1. 模块地图与线程归属

| 文件 | 职责 | 运行线程 |
| --- | --- | --- |
| `PerceptionChannel` | 亲密度计数（affinity）+ n-gram 热度滑窗（topic_heat）+ @ 兜底话题注记 | worker（observe）+ pollingThread（flushDue） |
| `PerceptionStore` | affinity 计数表（30s 或 delta≥100 批量 UPSERT） | pollingThread |
| `GroupListService` | 观察开关/监控群集**唯一真值**（DB），群列表镜像（含 member_count） | 任意（内部锁）+ pollingThread（poll） |
| `GroupContextStore` | 群消息短时缓冲（`group_messages` 表 + 内存镜像）+ 冷启动学习状态（`engagement_cold` 表） | worker（append）+ pollingThread（prune） |
| `GroupContextService` | 观察入库、@ 上下文装配（assemble）、收敛契约、转发激活/出站给会话 | worker |
| `EngagementService` | **话题会话状态机**：激活判定、轮次循环、上下文机制、收场与清扫 | worker（onGroupMessage）+ pollingThread（pump）+ 群 lane（runTurn） |
| `GroupLineFormat`（ADR-026） | 群聊材料一行的唯一格式化点：`formatGroupLine`（`[HH:MM] 名字: 正文`，引用回复时画出回复的是谁的哪句）、`GroupReplyIndex`（按 `messageId` 查，由调用方手里的全部记录构建）；纯函数 | 调用方线程 |
| `GlanceService`（R1.1） | **群聊瞥视**：入站群图异步瞥视成一行派生描述写回群缓冲占位符；每群每分钟预算 + 队列封顶 64 + 字节去重；零行为变化 | worker（observe 入队）+ 自有瞥视 worker（视觉调用与写回） |
| `ReflectionService`（经历层 E3，ADR-030） | **回想**：到期判断、按群去重的队列、材料装配（全在内存）、调模型、读法写反馈、认识增改写账本；prompt 与解析在纯函数 `src/Affect/Reflection`（见[文末附](#附回想经历层-e3adr-030)） | pollingThread（pump：节流后判到期并入队）+ 消息 worker（`reflect_now` 入队）+ 自有回想 worker（`runNow`） |

门控三重：`featureEnabled()` && `isMonitored(groupId)` && 群聊消息。总开关与监控集为**运行时状态**（`perception_meta` / `group_cache` 表），面板改动落库即时生效，但 **Store 仅在启动时按开关构造**——开关关闭期间启动的进程，运行中打开开关需要重启才有内容库（面板标注"需重启"即此语义）。

任务提交：会话轮进 `KeyedTaskScheduler` 群 lane（`groupId | 0x8000'0000'0000'0000` 高位标志避免与 user_id 撞车），同群串行、跨群并行，模型调用绝不阻塞 worker/polling 线程。

`group_messages.text` 的图片占位符可被瞥视层**原地改写**（R1.1）：`[image asset_id=X source=inbound]` → `[image asset_id=X source=inbound | 描述]`（或 `| 未看（刷屏）`），经 `GroupContextStore::findText`/`updateText`（锁内改镜像、锁外 UPDATE）；描述是派生文本，与该条消息同 300 条/24h 生命周期。贴纸占位符为 `[image asset_id=X source=inbound sticker]`，mface/face 表情拼成 `[表情 狗头]`/`[表情 face:14]`。

## 3. 激活：三个入口

### 3.1 @ 硬激活（必须回答）

`Message::handleMessage` 群聊 @ 分支 → `GroupContextService::onAtActivated` → `EngagementService::onAtActivated`：无存活会话则**清旧建新**（旧上下文让位落日志），有存活会话则仅记活动。回答本身走既有回复路径（assemble 上下文 + 全套工具 + 人格 + 收敛契约），**不经话题会话轮**。@ 消息同时被 observe 入库。生效期（`affect.enforce=true` 且策略非基线）判定器对 @ 可以选 `no_reply`：不请求表达模型、不发任何东西，执行记录 `skipped`（2026-11-22，见[附：去闸](#附去闸入场出场由她定adr-031)）。

### 3.2 提名字直入入场轮（她本人判断，2026-10-31 起）

`mentions_bot` = @ 她，或正文含 `bot.name` / `bot.aliases`（单个名字，2026-11-08 起由数组改为字符串；ASCII 不区分大小写，`BotIdentity.h::mentionsBotName`，2026-10-30 起；此前仅区分大小写匹配 `bot.name`，群友叫"克莱茵"不算点名）。

`observe` 入库后 `onGroupMessage` 发现 `mentions_bot && !at_mentioned && !is_self` 且无存活会话 → 过**提名字激活预算**（`allowNameActivationLocked`）→ 锁内清旧建新（来源"提名字"，话题行 = 触发句）+ `entry_pending=true` → 释放锁后 `submitTurn` 提交入场轮（群 lane）。不经杂务模型、不做字符串判定：**是不是在叫她，由她本人（人格主模型）读现场决定**——入场轮 ask 告诉她"有人提到你的名字但没有 @ 你"，并在末尾附上"提到你的那句是：「触发句」"；是在叫她就 `group_say` 自然回应，只是聊起她、顺嘴用到这个词或无话可接就 `leave_topic`（沉默同样自然）。入场轮里不调工具同样算"不接"（直接写出的文字不算说话，见 §4.2），会话直接收场，不会被后续轮次追问。她自己选沉默没问题，被管道拦下才是缺陷。

**激活预算**（资源护栏，不是行为规则）：每群 60 秒最小间隔 + 滚动 1 小时窗口内 ≤6 次；放行即记账。会话建立是同步的，存活期间的再次提名字走点名轮（§4.1），无需合流标记。

**缘由（2026-10-31 14:10 真机）**：群友说"克莱茵在吗"（别名点名），旧软激活先交杂务模型判定器（最近 6 条 + 只许输出 `YES`/`NO：理由`），模型照抄指令回了"介入输出 YES"，`runJudge` 只认以 `YES` 开头的回复，记成"话题介入判定 NO"，没人回她。产品定规：无 @ 的点名是否在叫她，必须由她本人读上下文判断，不能由独立廉价分类器加字符串 `if` 决定。`runJudge` / `judgeSystemFor` / `setSubmitJudge` / `pendingJudge` / `kJudgeWindowMessages` 随之删除。

### 3.3 冷启动自动介入（热度尖峰自决，2026-09-17）

无人生成互动的火热对话也能进入。每群 `ColdState`（纯内存桶计数 + **持久化学习状态**）：

**阈值模型**：

```
expected_daily = max(人数 × 0.2, hourly_ema × 24)     # 人数给冷启动先验，EMA 管学习
基线（10 分钟桶）= expected_daily / 144
触发阈值 = max(6, 人数 × 3%, 基线 × 3)                 # 地板防死群噪声，倍率抓真尖峰
尖峰 = 最近 10 分钟消息数 ≥ 触发阈值
```

- `hourly_ema`：每小时采样一次"最近 1 小时消息数"，`ema = 旧值×0.7 + 样本×0.3`
- **武装期**：首条消息起 2 小时内不启用（基线未成形）
- **持久化**：EMA/武装期/当日评估计数 write-through `engagement_cold`，重启续用（冷却截止一列保留、2026-11-21 起恒写 0）；桶计数是实时数据不落库，从活流量自然回填

**触发动作**：无存活会话 + 不在退场期 + 尖峰命中 + 上次评估不在同一个尖峰桶窗口内（`kSpikeBucketSeconds`，“同一波热度只看一眼”，2026-11-21 起取代当日帽与冷却，见[附：去闸](#附去闸入场出场由她定adr-031)）→ 开冷启动会话（`cold_pending=true`）→ 直接跑**冷入场轮**。不设独立 judge——带人格的主模型看最近 15 条材料，ask 明示"**没有任何人点名你**，是否主动加入由你的性格决定"；高冷人格自然少介入，`leave_topic` 与沉默都是正当自决（沉默在冷入场轮直接收场，不计 pass 连击）。入场轮之后会话与普通会话无异。

**频控总表**：

| 机制 | 提名字激活 | 冷启动 |
| --- | --- | --- |
| 最小间隔 | 60s/群 | 60s 检查节流 |
| 小时/日帽 | ≤6 次/小时 | 无（2026-11-21 去掉当日帽） |
| 介入后冷却 | —（会话照常） | 无（2026-11-21 去掉）；同一波热度只看一眼：上次评估在 `kSpikeBucketSeconds` 内不再评估 |
| 合流去重 | —（同步建会话，后续提名字并入会话） | —（pump 单点触发） |

## 4. 会话轮循环

### 4.1 轮次触发时机

| 类型 | 条件 | ask 变体 |
| --- | --- | --- |
| 入场轮（Entry） | 提名字激活后首轮 | "有人提到了你的名字但没有 @ 你……根据上下文判断是在叫你还是只是聊起你；叫你就 group_say 自然回应，否则 leave_topic"，末尾附"提到你的那句是：「…」"；沉默 = 她决定不接，**直接收场**（与冷入场轮一致，不计 pass 连击；2026-10-31） |
| 冷入场轮（ColdEntry） | 冷启动尖峰后首轮 | "**没有任何人点名你**，只是群里刚热闹起来。先读一遍：看不懂就挑最关键的一点问一句、查一下，或者不出声；看懂了、确实有想说的再用自己的方式加入；leave_topic 同样正确"（2026-10-31 诚实优先改写） |
| 点名轮（Address） | @ / 提名字 / 引用回复她 | "有人叫了你的名字或回复了你：先看清是不是在跟你说话……是就通常该接住再 group_say；不是在叫你或没什么可说，沉默也自然"（2026-10-31 去掉"必须回应"，接不接由她判断）
| 跟进轮（FollowUp） | lull：自上轮攒 ≥5 条新消息 + 群内静默 ≥4s + 距上轮 ≥75s + **每小时 ≤8 次**（2026-09-17 趁热插话；2026-09-18 真机反馈二次定规：回得太勤、每个话头都接是"人机味"第一来源，故回调加帽；点名/入场/追问轮不受小时帽限制） | "先看再动：有想接的就接" |
| 追问轮（FollowUp，2026-10-31） | **追问窗口**：她上次在会话轮开口（`group_say` / 离场最后一句，记 `lastSpeakTs`）后 ≤120s + 自上轮 ≥1 条新消息 + 群内静默 ≥4s + 本次开口后追问轮 <2（`followUpTurnsUsed`，她再开口归零）+ 无待执行的点名/入场轮 + 不在退场期（2026-11-16 起；同日加的份额门 2026-11-21 去掉，见 §4.4）。不计 lull 每小时帽、不受 75s 节流；本拍已提交追问轮则跳过 lull | 同跟进轮（`kFollowUpAsk`，可沉默；沉默照常计 pass） |

点名为最高优先级（点名与入场同时pending时按点名处理）。没人叫她的轮次（追问窗口、lull、冷启动入场）在她自己请求的退场期内不提交；2026-11-16 加的发言份额门已于 2026-11-21 去掉，份额只记账、交给判定器，见 §4.4。追问窗口的起因（2026-10-31）：她问"lulu是谁？"，群友答"崩三前瞻主持人"却不引用不点名——此前要再攒 5 条 + 75s 才轮得到她，答案早被刷走。窗口与轮数只是资源预算，说不说仍由她在轮内决定。轮次经 `runTurn`：锁内快照（硬后盖复查 + store 快照 + 摘要水位）→ **锁外**做压缩与模型调用 → 锁内按 `startTs` 校验会话未被替换后落地效果。

### 4.2 动作协议（每轮三选一）

| 动作 | 形态 | 效果 |
| --- | --- | --- |
| `group_say(text)` | 工具调用 | text 原样发群 + 入库（is_self），轮次 +1、pass 清零 |
| 不调工具 | — | 本拍沉默（直接写出的文字一律不发，见下）；计一拍 pass（`consecutivePasses` 只计数进情境卡，2026-11-21 起不再收场） |
| `leave_topic(reason, final_text)` | 工具调用 | final_text 非空则先发再关会话；reason 落日志 |
| `send_voice(text)`（2026-11-16，ADR-025） | 工具调用，只在语音可用时开放（`setTools` 名单含它） | 与 `group_say` 相同的发言，只是用语音送达：定案后调用同一个 `send_voice` 工具的 `execute` 合成，出站 `VoiceMessage{path, transcript}`，合成失败或工具此刻不可用时发原话文字；入群缓冲存原话 |

**只认工具调用里的话（L3 程序护栏，2026-11-14）**：发进群里的只有 `group_say` 的 text 与 `leave_topic` 的 final_text。不调工具时，不论 content 是否为空，一律按沉默处理（计一拍 pass；入场/冷入场轮直接收场），会话推进与决策/执行记录和她主动选择沉默完全一样（执行 `skipped`、`actual_text` 为空）；content 去首尾空白后非空时记一条 `LOG_WARNING`，只记码点数与群号——那段文字可能引用了群友的话或昵称，原文不进日志。定案判定的唯一实现是 `Application/EngagementTurn` 的 `parseEngagementTurn`（纯函数，runTurn 在工具轮之后调用）。此前的"宽容规则"把无工具的非空裸文本当成发言，与契约"文字内容只有经 group_say 才会被发出"矛盾：她常把"为什么不说话"写成一句旁白，截至 2026-11-14 主动轮发进群的 459 条消息里有 5 条整句就是这种旁白（如"（没有说话，继续留意后续）"）。被 @ 的回复与私聊走 `ChatService::reply`，不经这里。`group_say` 空文本按沉默处理；冷入场轮的沉默 = 自决不加入，直接收场（不计 pass）。模型每轮可先走工具轮再定案（见下）。

**工具轮（2026-10-30 起）**：定案前主模型可调用两类非定案工具——会话工具 `recall_context`（见 §5）与组合根经 `EngagementService::setTools(&tools, {"inspect_image", "generate_image", "send_image"})` 开放的**注册表工具**（当前为三个图片工具，2026-10-31 起加 `klein_web_search`/`klein_web_fetch`——组合根列表为 `{"inspect_image", "generate_image", "send_image", KleinWebSearchToolName, KleinWebFetchToolName}`，联网未配置时未注册即被丢弃；`setTools` 当场过滤，未注册或 `requiresAdmin()` | **不活跃** | 群内 10 分钟无新消息 | 自然结束（`话题沉寂`） |
| 连续沉默 | —（2026-11-21 去掉） | 不再收场；`consecutivePasses` 只计数进情境卡（[附：去闸](#附去闸入场出场由她定adr-031)） |

### 4.4 在场账本：发言份额与退场（ADR-024，2026-11-16）

每群一份 `affect::GroupPresence`（`src/Affect/GroupPresence.h/.cpp`，纯逻辑，`EngagementService` 持有、会话锁内调用），是两条发言路径（Message 的 @ 回复、本卷的会话轮）共用的唯一事实来源。§4.1 的触发规则只管“什么时候看一眼”（模型调用开销）；账本记下她和别人各说了多少，2026-11-21 起只记账、交给判定器（见下）。

- **记什么**：别人的每条消息（`onGroupMessage`，`isSelf` 除外，与会话状态无关）；她说出口的每一句，按应答 / 主动记。会话轮在定案处记：`Address`、`Entry` 轮的发言与离场最后一句记应答，`FollowUp`、`FollowUpWindow`、`ColdEntry` 轮记主动；@ 回复由 `Message` 在确有出站时调用一次 `GroupContextService::onAtAnswered` → `EngagementService::onAtAnswered`，记应答（分条发送只记一句）。`GroupContextService::recordOutbound` 只管入库，不再通知跟进（原 `onSelfActivity` 删除：入库这一层分不出两条路径，@ 回复会把会话轮的追问预算一并重置）。
- **发言份额**（`mayVolunteer` 的口径）：最近 10 分钟里，(她的主动条数 + 1) × 其他发言人数 ≤ 其他人的消息总数，即她主动说的话不超过其他人平均每人的条数；窗口里没有别人的消息时不主动开口。应答不占份额；她自己说话永远不会让份额变多，份额只随别人说话、随时间滑出窗口而恢复。2026-11-21 起这只是一本账（ADR-031）：`pump` 不再问 `mayVolunteer`（它只剩观测与测试用），窗口内的四个数写进情境卡（`unprompted_in_window` / `answers_in_window` / `others_messages_in_window` / `other_speakers_in_window`，会话轮由账本的 `view` 取；@ 路径的情境卡由 `atReplySituation` 装配、不读账本，不填这四项，恒为 0），判定提示写明“要不要再主动开口由你看着它定，程序不设份额”。
- **离场（两条路径共用同一动作）**：会话轮的 `leave_topic` 动词与 @ 回复路径的 `leave_topic` 工具（`src/Tool/LeaveTopicTool.h`，只在群聊开放，组合根 `bind` 到 `EngagementService::leaveTopic`）都落到 `leaveLocked`：结束存活的会话；参数 `step_back=true`（被请走）时另进入 30 分钟退场期。退场期内账本不允许主动开口；`onAtActivated` 不开新会话（@ 仍由 Message 照常回答），提名字不开会话，冷启动不评估。不带 `step_back` 的离场与此前一样只结束这次跟进（入场轮“不是在叫我”就是这样离场的）。
- **起因（2026-11-16 10:47–10:53 真机）**：换成几乎每轮都开口的模型后，追问预算“她一开口就归零”，6 分钟里她在一个群说了 20 多条；三次 @ 让她停下，@ 回复反而经 `onSelfActivity` 重开了追问窗口。同节奏回放在份额做门时她说 6 条（纯账本口径仍由 `GroupPresenceTest.IncidentReplayStopsHerAtTheAverageParticipant` 钉住）；去闸后会话层的回放改为 `EngagementPresenceTest.IncidentReplayHandsTheShareToTheJudge`：程序不再拦，账本的数进情境卡。
- **规则常数**：`affect::PresenceRules{shareWindowSeconds=600, withdrawSeconds=1800}`，代码常数，不是配置键；账本是进程内状态，重启即空。

## 5. 上下文机制（prepareContext）

入场/追问/跟进/冷入场统一走一套装配：

```
1. fresh = store 快照中 ts > compressedUpToTs 的消息（时间序），最多取最近 30 条
2. 单条文本 > 1000 token（UTF-8 启发式：CJK 1 token/字，ASCII 1 token/4 字符）
   → 保头 120 字截断、退到最近句读收尾加"……（后文略）"（保留发言人、时刻与语气，叙事不断裂）
3. 估算总 token = 已有摘要 + Σ窗口行；≤ 3000 → 摘要块 + 原文窗口直灌
4. > 3000 → 最旧一段（保底留最后 3 条原文尾巴）交轻量模型合并进滚动摘要：
   digest = mergeDigest(worker, kCompressSystem, 旧摘要, 段落)（Application/ContextDigest，与私聊滚动摘要共用，2026-11-08），水位 compressedUpToTs 前移
   轻量模型调用失败退化为仅尾巴原文
5. 产出：material + shownSeqs（本次真实展示过的 seq，供召回排除）
   每一行（原文窗口、压缩块、尾巴）都经 GroupLineFormat::formatGroupLine，回复索引按 store 快照全部记录构建（ADR-026）
6. runTurn 拼 user 消息：material +（affect 开且接了部署者事实时）现场事实一行"（现在是……）" + 提问语；
   契约 systemNote 以部署者事实段开头（ADR-026，见附录）

材料最顶部注入**情绪基调行**：`（你现在的情绪基调——有惯性，接着这个状态说话，别突然归零）：<一句话>`。基调存于会话（`moodLine`，纯内存），每 3 个发言轮经 worker 低频更新一次（锁外调用，失败保留旧值）——跨轮情绪连续性的机制层（2026-09-18）。
```

- **召回**：`recall_context(keywords[2..4])` 工具——主模型出关键词（语义），`TextRecall` 词面匹配（无 embedding），在 `shownSeqs` 之外的记录里打分取 top8 回灌。**每会话限 1 次**，system 契约动态写明剩余额度；预算耗尽后 schema 不再下发
- **召回执行环**：主模型响应含 recall 调用 → 锁内校验并扣预算 → 执行 → assistant+tool 消息回灌 → 重新请求（与注册表工具共用工具轮，最多 3 趟，见 §4.2）→ `parseEngagementTurn` 定案

- **手动**：`requestNow(群号)`（`reflect_now` 工具；群号为 0 = 所有有过决策的群）不受间隔、当日次数与退避限制，但“有没有待回想的经历”与自动调度同一判据：游标同样先套地板，所以只有 `kLookbackSeconds` 之前旧决策的群不入队。已排队或正在回想的群不重复入队（还在队列里的那一次升级为手动）。结果 `ReflectionRequest` 分别计数：这次排上的、正在回想的、已在排队的，以及服务不可用（affect 关着、账本打不开或已停止）；`reflect_now` 据此如实回复，不把“已经在排 / 正在想”说成“没有待回想的经历”。
- **开关与模型**：`affect.enabled` 当前为假时 `pump`、`requestNow`、`runNow` 什么都不做、不打开账本；为真时按与账本工具同一判据打开（第一次到期判断就会打开账本建表）。调用目标每次回想开头解析一次：`memory.model` 在注册表里就用它，否则 `models.worker`，worker 也没配时回退默认对话模型（组合根用 `resolveLabeledEndpoint`，记录的模型名与调用的成对）。没写 `memory.model` 时加载阶段把它填成 `chat.default_model`（`ConfigLoader.cpp`），所以默认部署下回想用的就是主对话模型；只有 `memory.model` 不在注册表里（例如写了未注册的名字）时才回退到 `models.worker`。想让回想用便宜模型，要显式配置 `memory.model`。
- **进度**：`perception_meta` 键 `affect.reflection.<群号>`，值是 JSON `{cursor, cursor_decision, last_run, day, runs_today, retry_after}`，`cursor_decision` 是游标那一秒里最后看过的决策号；没有这个字段的旧进度按“那一秒都看过了”读（与只比 `created_at > cursor` 相同），下次写回时补上（[卷13 附](13-持久化层.md#附人物卡取用与回想用到的存储adr-029adr-030adr-032)）；读不出时按从头算（游标仍套地板）。

常量（`affect::ReflectionRules`，`src/Affect/Reflection.h`；最后两个在 `ReflectionService.cpp` 的匿名命名空间里）：

| 常量 | 值 | 作用 |
| --- | --- | --- |
| `kIntervalSeconds` | 6 h | 每群自动回想的最小间隔（从上次回想算起，含手动） |
| `kDailyCap` | 4 | 每群每天（本地日历日）自动回想次数 |
| `kAftermathSeconds` | 20 min | 后续窗口：决策之后这么久才算“后来怎样”已定 |
| `kAftermathMessages` | 30 | 每次经历之后至多带几条现场 |
| `kBystanderMessages` | 60 | 她没参与的群聊至多几条 |
| `kExperiencesPerRun` | 10 | 一次回想至多看几次经历（沉默、离场也算） |
| `kEarlyTriggerMessages` | 200 | 最早一次未回想经历之后群缓冲积到这么多条就提前回想 |
| `kMaxReadings` | 16 | 模型一次最多给的读法条数（多的丢弃） |
| `kMaxReadingCodepoints` | 120 | 读法一句的码点上限 |
| `kTimeoutMs` | 120 s | 回想模型调用的超时 |
| `kLookbackSeconds` | 24 h | 游标地板：群缓冲只留 24 小时，更早的经历没有现场可看 |
| `kRetrySeconds` | 30 min | 模型没返回后的自动回想退避 |
| `kPumpIntervalSeconds` | 60 s | `pump` 内部节流 |
| `kScanLimit` | 60 | 一次最多扫几条决策找经历 |

- **线程**（[卷22](22-并发与线程模型.md)）：服务自有一条工作线程（`start` 起，组合根在 `pollingThread` 之前调用）。输入是按群去重的队列（`deque<Job>` + 已排队群的 `set`，每群至多排一次；手动请求遇到已排队的同群任务时把它升级为手动；在已排队集合里却不在队列里 = 工作线程正在回想它，`requestNow` 据此区分“已排队”与“正在回想”），入队后 `notify_one`；工作线程 `wait` 到有任务或停止，取一个群、在 `queueMutex` 之外跑 `runNow`，跑完把这个群从已排队集合里去掉。同群不会并行、游标在这次回想写完后才前移，所以一次经历至多回想一次。`shutdown`：置停止标志、清空队列、`notify_all`、join；进行中的模型调用随 `running=false` 由适配器取消。`pump` 在未 `start` 或已停止时是空操作。
- 不加配置键、表或字段。观测点见 §9；测试：`ReflectionTests.cpp`（[卷21](21-测试体系.md)）。
