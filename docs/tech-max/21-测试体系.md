# 卷 21 · 测试体系

> 源码基准：`tests/`（C++ 测试文件、契约测试驱动程序与 Python 测试）、`tests/CMakeLists.txt`。`WebSearchTests`、`WebFetchTests` 各有一个需要真实外部服务的用例，没设 `KLEIN_TAVILY_API_KEY` / `KLEIN_WEB_FETCH_TEST_URL` 时按预期跳过。测试基于 GoogleTest + CTest；**自动化测试绝不调用真实模型 API**（Fake/Mock 适配器 + 临时数据库/目录）。

## 1. 目标与产物

| 目标 | 说明 |
| --- | --- |
| `kleinbot_tests` | 链接 `kleinbot_core` + `gtest_main`；`gtest_discover_tests` 注册每个 TEST 为独立 ctest 项 |
| `transport_contract_driver` | 独立小可执行文件，被 Python 契约测试当黑盒驱动 |
| `panel_page_sync_tests` | 把 panel.html 同步到测试工作目录（GET / 用例现读） |
| `TransportContractPython` / `ArchitectureDependencyPython` / `AffectEvalExportPython` | Python3 可用时注册进 CTest |

运行：

```bash
cmake --preset linux-debug && cmake --build --preset linux-debug
ctest --preset linux-debug                  # 全量（outputOnFailure）
./build/linux-debug/tests/kleinbot_tests --gtest_filter=MemoryRecall*   # 单跑
```

窄测优先：改哪块先跑对应文件的用例，再全量（AGENTS.md 规则）。

## 3. Python 契约测试

### 3.1 transport_contract_test.py（347 行）

以 `transport_contract_driver` 为黑盒，对**传输与编解码契约**做跨语言验证：服务器模式、客户端模式、HTTP 三种传输各起一个驱动进程，脚本扮演协议端，断言驱动发出的 OneBot action 结构，回送一条事件后断言驱动输出的 JSON；错令牌须得到 401。防止 C++ 侧编码协议漂移。

客户端模式另在成功会话之前检查监听器常驻（2026-11-26，见[卷05 §4](05-网络与OneBot传输层.md#4-客户端模式-websocketmyreversewebsocketcppreverse_websocket)）：连续 20 次错令牌握手每次都得 401；下一个连接在上一个拿到 401 之前就排进积压队列，也必须得到 401 而不是被重置；连上即断、发送非 HTTP 数据的连接之后，下一次握手须在 2 秒内完成。

### 3.5 持续集成（GitHub Actions，2026-11-25）

`.github/workflows/ci.yml`：`pull_request` 与推送到 `main`、版本分支（形如 `2.4.2`）时，在 `ubuntu-22.04` 上跑 `cmake --preset linux-debug`、`cmake --build --preset linux-debug`、`ctest --preset linux-debug`，与本地用的是同一组预设命令。依赖全部取自系统包：`g++ make cmake git libboost-dev libcurl4-openssl-dev libsqlite3-dev libgtest-dev python3 tzdata`（`tzdata` 是因为 `FactsCardTest` 与 `GroupLineFormatTest` 各有一项把 `TZ` 设为 `Asia/Shanghai`，没有时区数据会按 UTC 计算而失败）。
