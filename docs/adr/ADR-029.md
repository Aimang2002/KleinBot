# ADR-029：经历层取用：认识进判定与表达

- 状态：已采用
- 日期：2026-11-21

> 文中的“§x.y”指 [technical-design.md](../technical-design.md) 的章节。

## 决策

经历层取用：认识进判定与表达（2026-11-21，经历层设计（内部笔记） §7/§12 的 E4，部署者决定先于 E3 实施；分支 `feat/v2.4.2-experience-retrieval`，基于 `2.4.2@45a330f`，2026-11-21 提交 `e4afdda`、ff-merge 合入 `2.4.2` 并推送，线上 02:53 起运行）——①**取什么**：全局的 + 本群的 + 现场的人的（会话轮 = 材料窗口里的群友 + 回复候选的发言者，@ 回复 = 群背景入选的群友 + 触发句发送者；person 的 scope_group 为 0 或本群），只取 active 且读时算出的有效强度 ≥ 0.15（教导不衰减）；热路径只读，不跑遗忘、不写库（新读方法 `KnowledgeLedger::recallPool`，同一把锁）。②**挑哪些**（纯函数 `Affect/KnowledgeRecall` 的 `selectKnowledge`）：教导永远优先，其余按有效强度降序截断（判定器 `kJudgeKnowledgeMax = 10`、表达 `kReplyKnowledgeMax = 6`，代码常量），截完按条目编号升序输出——强度衰减时文本不变，只有条目进出或改写才变；不做文本召回。③**怎么拼**：标题行“[你的认识]”，之后一行一条原文，不带编号、强度、来源；没有条目不加。④**放哪**（全部在本轮 user 侧尾部，system 与缓存前缀不动）：判定器 prompt 里紧跟“此刻”、在可回应的消息与现场材料之前，带引语“她的认识（账本里她记下的与部署者教的；其中的“你”指她）：”（与“关于她的事实”同一组，不混进标着不可信的材料；三者都在 user 侧）；会话轮在现场事实那一行之后、提问语（含 `kPlannedAsk`）之前；@ 回复并入 `tailNote`、接在现场事实之后，经 `appendContextNote` 尾插；私聊不取用。⑤**开关**：当次 `affect.enabled` 为真且组合根接了账本（与 `factsCardFor` 同一判据）；关着、账本为空或没有匹配条目时请求逐字不变；重启后由取用按同一判据打开账本。⑥**记录**：判定器看见的编号写进决策记录 `state_json` 的 `knowledge_ids`（没取用时不写）。不加配置键、表或字段；顺手把 `KnowledgeAction` 的 `timeText` 缓冲区放大到 64 字节，消掉发布版的 `-Wformat-truncation` 告警

## 原因

E2 之后账本里有了部署者教的认识，但它们不进任何请求，教了等于没教。按编号排而不是按强度排：认识段每轮都在请求尾部，衰减不该让文本天天变；教导优先：部署者的纠正分量最高（设计 §6）。放 user 侧尾部与事实卡里的现场事实同一规矩（§13.4 前缀缓存）

## 代价

affect 开着时群聊判定与两条群聊表达请求都多一段认识（有条目时）；第一次群聊判定会打开账本，没用过账本工具的部署会在决策库里建出两张空表；基线策略下表达带认识但记录里没有编号；judge 回退时编号照记；条目多于上限时只看教导与强度、不看相关性；教导回放（离线回放实验，deepseek-flash）：全局的一句两条路径都吃进去，按人的一句改了长度档，本群的「深夜少说话」只压住现状路径
