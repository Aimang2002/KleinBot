# ADR-032：人物卡：确定性加载的对方卡片

- 状态：已采用
- 日期：2026-11-22

> 文中的“§x.y”指 [technical-design.md](../technical-design.md) 的章节。

## 决策

人物卡：确定性加载的对方卡片（2026-11-22 部署者定，经历层设计（内部笔记） §15；分支 `feat/v2.4.2-experience-retrieval`，2026-11-22 提交 `44847c5` 并 ff-merge 合入 `2.4.2`，已推送、线上 01:42 起运行）——①**卡片** `Memory/PersonCard`：固定槽位，程序给出的（QQ 号、昵称快照、是不是部署者——只由 `bot.manager_id` 算出、建卡日期——只存不显示）与她自己记的（`wanted_name` / `my_name` / `name_for_me` / `note`×5）。②**存储**：不建表不加列，复用长期记忆事实表（`subject_key='user:self'`、谓词前缀 `card.`，`MemoryStore::cardSlots / setCardSlot`，经 `MemoryService` 对外并带代数 `cardGeneration`）；批量提取跳过这个前缀；按人清除、按来源回滚沿用事实表。③**加载**：私聊进 system（稳定文本，人格之后）；群聊 @ 回复并入尾注、会话轮放在现场事实之后与她的认识之前，在场的人各一行、只写有内容的、部署者最前、至多 8 人；判定器 `SituationCard::peopleSection` 排在她的认识之前；`GroupLineFormat` 在部署者昵称后加“（部署者）”。④**更新**：工具 `update_person_card`（`Action/PersonCardAction`，私聊与群聊都开放、不要求管理员），当场写库并使缓存失效；护栏只有槽位白名单、一行、≤ 40 码点。⑤**开关**：`memory.enabled` 为真且记忆库可用；否则请求逐字不变。不加配置键

## 原因

实测（离线回放、真实召回代码）：带疑问词的提问召回 11/14，寒暄与不带疑问词的 0/7 触发——“她一开口就知道对方是谁”不能靠召回；批量提取有 10 轮 / 30 分钟的延迟，“叫我小白”不会当场生效；她此前只知道“有个部署者”，不知道群里哪个人是

## 代价

记忆开着时：私聊 system 多一段卡片（首次私聊与 @ 会在库里写一行建卡日期，不显示）；群里只要部署者在材料里，就多一行“在场的人”与行内标记；她可以给任何人记称呼与 note（含群里别人让她记的——由她判断）；卡片事实也会被事实召回查到；私聊还不取用认识账本
