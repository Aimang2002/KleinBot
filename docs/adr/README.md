## 什么时候写一条 ADR

- 推翻或修改上面任何一条决策。
- 放宽对外接口的非目标，或推倒一个草案契约（见 [AGENTS.md](../../AGENTS.md) 的“窄腰模型与接口生命周期”）。
- 给核心增加新的通用能力，或改变分层与依赖方向（见[设计哲学](../design-philosophy.md)）。

只影响某个边缘模块内部的实现选择，不需要 ADR，写清楚提交信息即可。

## 怎么写

- 编号取下一个没用过的（当前用到 032），文件名 `ADR-NNN.md`。
- 开头是标题、状态、日期，正文分“决策”“原因”“代价”三节，格式照现有文件。
- 写决策本身和理由，不写开发流水。分支名、提交号、何时上线属于提交信息；较早的几条里带着当时的开发状态，保留原样，新写的不要这样。
- 已采用的 ADR 不改写正文。决策变了就新增一条，并把旧的那条的状态改成“已被 ADR-NNN 取代”。
- 在 [technical-design.md](../technical-design.md) §3.8 的索引里加一行。
- 和其他公开文档一样：不得出现密钥、真实的 QQ 号或群号、聊天内容、只在本机成立的路径。
