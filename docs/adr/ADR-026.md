# ADR-026：经历层 E0：事实卡与回复关系

- 状态：已采用
- 日期：2026-11-16

> 文中的“§x.y”指 [technical-design.md](../technical-design.md) 的章节。

## 决策

经历层 E0：事实卡与回复关系（2026-11-16，经历层设计（内部笔记） §4/§12 的第一步；分支 `feat/v2.4.2-experience-e0`，基于 `2.4.2@4a39e80`，未提交）——①**事实卡** `src/Affect/FactsCard.h/.cpp`：现场事实 `sceneFactsNote(now)` 由程序算出（运行机器本地时间的日期、星期、时刻，加“这一轮你能用的工具，就是提供给你的这些。”）；部署者事实来自可选文件 `source/facts.md`（与 `soul.md` 同目录，`DeployerFacts::read` 每次现读，改了下一次请求即生效；缺失或去首尾空白后为空就不加；超过 4096 字节按 UTF-8 边界截断并记一条只含长度的 WARNING），格式化成“[关于你的事实] 由部署者填写，是真实情况：”一段。②**放置**：部署者事实是稳定文本，进 system，紧跟人格与服务契约——会话轮的 `systemNote` 以它开头（影子与生效两种契约都一样），@ 回复接在群聊收敛契约之后；现场事实每分钟都变，绝不进 system，只进本轮 user 侧的请求副本、不落库——会话轮在材料之后、提问语之前加一行“（现在是……）”，@ 回复并入尾注 `tailNote`，经 `appendContextNote` 以“[系统注]”尾插。判定器经 `JudgePolicy::setFactsSource` 自己在 prompt 里加“关于她的事实”“此刻”两段，它拿到的现场材料不重复带那一行。③**开关**：只在当次 `affect.enabled` 快照为真、且组合根接了 `DeployerFacts` 时加（`affect::factsCardFor`）；关着时请求与此前逐字相同；只作用于群聊两条路径，私聊不动。④**回复关系** `src/Perception/GroupLineFormat.h/.cpp`：群聊材料一行的唯一格式化点（会话轮的原文窗口、压缩块与尾巴，上下文召回结果，@ 回复群背景的直灌块与摘要输入——此前七处各自手拼），引用回复时画出回复的是谁的哪句：`[15:51] 阿青（回复 你：「闲下来也挺好，摸鱼不用愧…」）: 也是`。被回复的是她写“你”、别人写昵称；引语取被回复消息的前 12 个码点，更长加“…”；只是图片、表情等非文字内容时写短词（“一张图片”），不抄 asset_id；目标不在缓冲里写“（回复了一条更早的消息）”；没有引用时与此前格式逐字相同。按 `messageId` 查的索引 `GroupReplyIndex` 由调用方手里的全部记录构建。这是感知层的忠实度，不受 `affect.enabled` 控制。不加配置键、表或字段；关于她的事实内容不写进可执行文件（用户 2026-11-16 定规）

## 原因

2026-11-16 回放：给模型“现在几号”和一份部署者写的“关于她自己的事实”后，编造从约 24 处降到 5 处，问日期的现场 16/16 答对——她编日期、编来历，是因为手里没有这些事实。群聊材料原来只有 @ 回复的群背景写“（引用回复）”四个字，看不出回复的是谁，会话轮材料里连这几个字都没有。放置按供应商前缀缓存：system 在请求前缀最前端，逐字变化会让缓存整段失效，所以每分钟都变的现场事实放尾部（与 `ChatService` 图片路由注记同一规矩，§13.4），稳定的部署者事实才进 system

## 代价

打开 `affect.enabled` 不再只是“写记录”：群聊回复会带上事实卡；改 `facts.md` 后下一次请求的 system 前缀随之变化，缓存失效一次；她的消息在回执回填真实 `message_id` 之前被引用时，只能写成“回复了一条更早的消息”；事实卡里的工具一句是通用陈述，不逐个列出工具名；“这句 @ 了谁”仍未入库，画不出来（设计 §11 第 4 项，另起一步）
