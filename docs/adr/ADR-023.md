# ADR-023：配置实时生效：活值、规则表、稳定外壳

- 状态：已采用
- 日期：2026-11-15

> 文中的“§x.y”指 [technical-design.md](../technical-design.md) 的章节。

## 决策

配置实时生效：活值、规则表、稳定外壳（2026-11-15 用户批准，分 L0–L3 四阶段）——①**活值** `Live<T>`（`src/utils/Live.h`）：互斥量保护一个 `shared_ptr<const T>`，不可拷贝，没有 `->`、解引用与隐式转换，不带回调，`set` 是非 const 成员；模块只持 `const Live<T> &`，一次操作开头取一次快照，不把配置值再存回成员；组合根的 `LiveSettings`（`src/Bootstrap/`）每组配置一个活值，声明在所有服务之前。②**规则表** `Bootstrap/ConfigRules`：每个配置键一行（差异路径、生效方式、`field<成员指针链>` 比较函数），比较（`compareConfig`）、应用、反馈、测试与面板的字段说明（`GET /api/config/effects`）都遍历同一张表，档位只来自这里；生效方式只能由 `restart()` 与 `applies(应用函数)` 两个工厂产生（构造函数私有，`applies` 收函数引用、传不了空指针），没有应用函数就造不出 Dynamic；`Rebuild` 不再产生（枚举值与 JSON 名 `rebuild` 保留，对外形态不变）。③**唯一的“重载并应用”入口** `Bootstrap/ConfigReloader`：`#刷新配置文件` 与面板保存共用、串行化；校验不过什么都不变；通过后发布快照，再对变化里带应用函数的行执行应用（每个应用函数一次重载至多一次，只替换快照、不会失败）；反馈按规则表如实列出已生效与需重启的键。④**稳定外壳**：按开关决定是否构造的对象改为始终构造、地址稳定，内部读活值决定行为，运行时不建也不销线程（联网工具始终注册、按 `available()` 开放；记忆与瞥视线程常驻、开关在入队处读；决策库始终构造、第一次需要记录且 `affect.enabled` 为真时才打开建表，打开失败只试一次；策略外壳 `SwitchingPolicy` 每次决策按当前 `affect` 选基线或 judge）。业务模块不得包含 `Bootstrap/`（依赖测试机检）。**已落地**（特性分支 `feat/v2.4.2-live-config`，未推送、未合入 `2.4.2`）：L0（`0211a84`、`f319597`、`dc0f7cd`）与 L0.d（`f724866`，重载不再发布校验不过的候选）；L1.a–L1.f 数值类 45 键（`8b4d174`、`4d34af5`、`dfa616f`、`d58bf35`、`59cdef6`、`9eddf29`）；L2.a–L2.d 开关与对象类 9 键（`eab16f0` 工具可用性、`4f9056b` 记忆与瞥视开关、`8d1b250` 决策记录与策略、`8c11c10` 机器人名字与别名）；L2.e 收尾（`478b0ab` 按用户决定删除从未送进请求的 `chat.top_p`，旧配置里残留时只告警；`4efa6e8` `web_search.provider` 与 communication 17 键归 `restart()`、删除过渡工厂 `notYet`；`01104b8` 面板字段说明由规则表推出）。规则表 89 行：54 行 `applies`、35 行 `restart()`。**规划**：L3 默认人格进面板

## 原因

重载此前只换内存快照、没有任何业务模块读它，90 个配置键没有一个能不重启就生效，三档标签只是手填的标签（2026-11-15 迭代策划 §1，内部笔记）；把“标签”和“应用动作”绑在同一行，由类型系统保证标签如实，也让“新键是否实时生效”成为加键时必须回答的一栏

## 代价

十来个模块的构造签名与测试夹具改为持活值；规则表成为加配置键的关联点（`ConfigRulesTests` 的键数与 applies/restart 两份清单随之改）；面板字段说明不再手写生效方式（`ConfigPanelServerTests` 机检）
